directives-toolkit — commands

The 17 slash commands in the directives-toolkit plugin, grouped by development-pipeline phase (Think → Plan → Build → Review → Test → Ship → Reflect), plus cross-cutting helpers.

Type /<name> to run a command. For the always-current menu read live from the installed plugin, run /my-list. Auto-skills (update-pages, scope-chk, doc-comp) fire on their own and aren't listed here.

↻ marks the 4 commands the pipeline also runs — /kickoff and/or /sdd-loop invoke them. The other 13 are user-invoked; none are code-only.

Think

/diagnose
Forces the problem to be understood first — one diagnostic question at a time, 2–3 approaches with tradeoffs, then writes specs/<slug>/brief.md.
When — at the very start of any non-trivial feature or build, before /sdd-loop. No "too simple" exemption.

Plan

/kickoff
Kicks off a spec-driven build of a new app end to end — scaffold (if needed), gather the product brief, optional competitive discovery, then drive /sdd-loop.
When — starting a brand-new app from an idea.
/sdd-loop ↻
The Spec-Driven Development loop: specify → clarify → plan → tasks → analyze → implement, each step emitting a Markdown artifact that feeds the next, with the inherited directives as the constitution.
When — building any feature methodically once the brief exists.
/opt-3
Answers "should I do X?" as exactly three options — simplest, balanced, most robust — each with tradeoffs.
When — you want a structured decision instead of a single recommendation.

Build

/new-repo ↻
Bootstraps a brand-new project repo from scratch — scaffold, CLAUDE.md, CI workflows, plugin enablement.
When — the first session in a repo that has no CLAUDE.md yet (fires automatically then).
/design-intake ↻
Turns a starting look (image / Stitch HTML / Figma) into the project's reusable design contract — styles/tokens.css + styles/components.css + an approved reference page — then hands off to /sdd-loop.
When — at kickoff, or any time you want to establish or re-theme the visual identity.

Review

/audit-repo
Sweeps the repo for drift between the directives and the actual code, a recursive correctness check, and structural/organization improvements.
When — periodically on a fresh main, or when the repo has changed materially since the last audit.

Test

/commit-chk ↻
Manually runs the pre-push verification — tests, lint, the CI checks — before you commit.
When — as a backup to force the local gate before pushing.

Ship

/live-chk
Detects the repo's deploy mechanism and verifies the site is actually live and serving the latest deploy.
When — after a deploy, to confirm it really published (not cached or stale).

Reflect

/learn
Appends a typed, confidence-scored lesson to learnings.jsonl so future sessions consult it before recommending.
When — a session surfaces a durable pattern, pitfall, preference, decision, or tool fact worth keeping.
/handoff-session
Writes a delta-only, paste-ready handoff for a fresh session — only what no other repo file already captures (never a sidecar file).
When — ending a session that a future one needs to continue.

Cross-cutting

/env-chk
Full environment readiness check — session context, git health, CI status, validation gates, directive freshness, a connectors/tools inventory, and the repo-scope verification.
When — at session start, or whenever you're unsure the environment is sound.
/refresh-repo
Re-syncs the project with claude.directives mid-session — re-reads the rules, flags broken upstream references, and reports the upstream delta since the last sync.
When — mid-session, when the upstream directives may have changed.
/my-list
Shows every toolkit command and auto-skill as a clean menu, read live from the installed plugin so it never goes stale.
When — you want to see what's available in this session.
/do-repo
Runs a command — inspect / compare / audit — against any public GitHub repo via the API, with no clone.
When — investigating another repo read-only.
/browser-only
Locks answers to Chromebook browser-only constraints — no terminal, no local installs, no desktop apps.
When — you're on a Chromebook and want setup/answers that fit that.
/no-fluff
Strips formatting — bullets only, no preamble, no closing summary, no unsolicited recommendations.
When — you want terse, direct answers.
